Sumimi

Count kitties popping into my websites.

由猫开发 — a self-hosted web analytics service that fits on a cheap VPS.

Sumimi is a single-binary analytics server written in Rust. It stores everything in one embedded DuckDB file, serves its own tracker and dashboard, and makes no outbound network calls at all. Nothing to sign up for, nothing to pay for, nothing that phones home.

  • Rust + Axum + Tokio
  • DuckDB 2.0.0 embedded
  • One binary, one file
  • 1 vCPU / 512 MB RAM
  • Apache-2.0 licence
Install it Read the privacy promise API reference

What it is

Sumimi collects page views from your own websites and serves them back to you as statistics. The whole thing is one executable file plus one database file. There is no queue, no cache to operate, no object storage, no Kubernetes, no managed cloud service in the middle. You copy one file to a box, run one systemd unit, and you are done.

The HTTP API is Umami v2 compatible, so the official Umami dashboard — and the existing Umami tracker snippets — work against it unchanged. Sumimi is an independent open-source project; it implements the Umami v2 HTTP API and uses no Umami assets.

  • One file of data

    Everything lives in a single .duckdb file you can copy, back up or delete. No database server to install, secure or upgrade.

  • Nothing to phone home to

    No telemetry, no crash reporting, no update checks, no outbound requests of any kind. The server never talks to anything but its visitors and you.

  • Reads at a glance

    Page views, visitors, referrers, browsers, operating systems, devices, countries, languages and screens — over any time window, filterable by dimension.

  • An offline analyser

    The sumimi CLI reads the same DuckDB file directly, so you can query your traffic on a laptop with no server running at all.

Quick start

Five lines, on any Linux box with a spare gigabyte of disk:

# 1. download the release archive and unpack it
curl -fsSL https://github.com/sumimi-dev/sumimi/releases/latest/download/sumimi-linux-amd64.tar.gz | tar xz

# 2. install the one executable — it is both the server and the CLI
sudo install -m 0755 sumimi /usr/local/bin/

# 3. run it
sumimi serve --db /var/lib/sumimi/sumimi.duckdb --port 3999

# 4. drop the tracker into your website
#    <script defer src="https://your-host/sumimi.js" data-website-id="<uuid>"></script>

# 5. look at the dashboard at https://your-host/

The release archive contains sumimi — one executable that is both the server (sumimi serve …) and the analysis CLI (sumimi summary …) — plus the js/ directory with the dashboard frontend (and a copy of the tracker), and the docs/ directory with this documentation. DuckDB is compiled into the executable, so it is a single self-contained binary: there is no shared library to ship alongside it, and nothing else to install. The install guide has the full walkthrough, including Windows, macOS, the admin password and the systemd unit.

No website yet? sumimi seed --db ./demo.duckdb fills a database with synthetic demo traffic so you can look at the dashboard before pointing a real site at it.

The dashboard frontend is loaded from a CDN by default, so the server ships no frontend code and stays small; the tracker is compiled into the server binary and always served by it. See the self-hosting guide if you would rather serve the frontend yourself.

The privacy promise

Analytics software handles data that identifies people, so Sumimi treats the exclusions as acceptance criteria rather than options. The privacy page states them in full; the short version:

BehaviourSumimi
Cookiesnever set
localStorage identifiersnever used
Fingerprinting (canvas, fonts, audio, hardware)never attempted
Raw IP addressesnever stored, never logged
Visitor identifierrotating, non-reversible HMAC over a coarse IP prefix
URL query stringsstripped by default (opt in per site)
Do Not Track / Global Privacy Controlhonoured — nothing is sent
Geolocationonly from an edge header you configure; never from a geo-IP database
Outbound calls from the servernone, ever
Retentionconfigurable window, enforced by sumimi prune

One thing you have to take care of

Custom event properties are free-form data you supply. If you put an email address, a phone number or a user id in there, you have put personal data in your database, and every privacy guarantee on this page stops applying to it. The tracker never attaches anything sensitive on its own.

Why another analytics tool?

Most analytics services ask you to accept a privacy policy, hand your visitors' data to a third party, and then charge by the number of page views. Sumimi is the opposite: the software is Apache-2.0 licensed, the data stays on a machine you control, and the cost of running it is one small VPS you already have.

The self-hosting guide walks through a complete deployment on a 1 vCPU / 512 MB box: systemd, a reverse proxy, TLS via ACME, and backups you can actually restore from.
