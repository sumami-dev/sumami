The sumami-client CLI

The sumami-client command is the offline analyser that ships in the same release archive as the server. Like the server it is a single self-contained executable, with DuckDB compiled in — so there is no shared library to install alongside it. It answers the same questions whether it reads a .duckdb file directly or talks to a running server over HTTP — so the same command works on your laptop with the file copied over, and on the box itself.

The three executables

The release ships three self-contained binaries: sumami-server (the server only), sumami-client (this analyser) and sumami — the two-in-one, where sumami serve … runs the server and every other subcommand is the analyser.

Everything on this page uses sumami-client. If you installed the two-in-one instead, replace sumami-client with sumami and the commands behave identically.

Two sources, one interface

Pick exactly one source. Every subcommand below works in both modes.

ModeFlagsNotes
Local file --db <path>
(default ./sumami.duckdb)		 The file is opened read-only. prune and erase open it read-write.
HTTP API --url http://host:3000 plus --username/--password or --token Logs in as the admin account via POST /api/login and caches the token in ~/.config/sumami/credentials.json (mode 0600). 
# read a database file
sumami-client summary --db /var/lib/sumami/sumami.duckdb 3f2a...

# or talk to a running server
sumami-client summary --url http://127.0.0.1:3999 --username admin --password '...'

# with a token you already have
sumami-client summary --url http://127.0.0.1:3999 --token eyJhbGciOi...

Common flags

FlagMeaning
--db <path>The database file to read (local mode). Default ./sumami.duckdb.
--url <url>Base URL of a running server (HTTP mode).
--token <token>Bearer token for HTTP mode. Bypasses the credential cache.
--username <name>Admin username for HTTP mode.
--password <pass>Admin password for HTTP mode.
--jsonMachine-readable output instead of a table.
--from <date>Start of the window. An ISO date or a relative range like 7d.
--to <date>End of the window. Same format as --from.
--limit <n>How many rows to show, on the row-based reports. Default 50.

The website id is a positional argument, not a flag: sumami-client pages 3f2a.... --from, --to and --limit come after it. summary takes the website id and the window but no --limit; websites takes no arguments at all.

The source flags have environment equivalents: SUMAMI_DB, SUMAMI_URL, SUMAMI_TOKEN, SUMAMI_ADMIN_USER and SUMAMI_ADMIN_PASSWORD.

Commands

websites

List the websites in the database or known to the server.

sumami-client websites --db ./sumami.duckdb
ID                                 NAME       DOMAIN              CREATED
3f2a1b4c-5d6e-7f80-9a1b-2c3d4e5f6071  My Blog    blog.example.com   2026-01-12
7c8d9e0f-1a2b-3c4d-5e6f-708192a3b4c5  My Shop    shop.example.com   2026-02-03

summary

The headline numbers for a window: page views, visitors, visits, bounces and average visit duration. 

sumami-client summary --db ./sumami.duckdb 3f2a... --from 7d
METRIC          VALUE
pageviews       1523
visitors         842
views            611
bounces          233
visit duration     84s

pages

The most visited paths.

sumami-client pages --db ./sumami.duckdb 3f2a... --limit 5
VIEWS  URL
  312  /posts/hello
  254  /posts/world
   98  /pricing

referrers

Where the traffic came from.

sumami-client referrers --db ./sumami.duckdb 3f2a...

browsers

The browser breakdown. The operating system, device, country, language and screen breakdowns each have their own subcommand: os, devices, countries, languages and screens. They take the same arguments and print the same shape of table. 

sumami-client browsers  --db ./sumami.duckdb 3f2a...
sumami-client os       --db ./sumami.duckdb 3f2a...
sumami-client devices  --db ./sumami.duckdb 3f2a...
sumami-client countries --db ./sumami.duckdb 3f2a...

events

The custom events, with their properties.

sumami-client events --db ./sumami.duckdb 3f2a...

Event properties are yours

Custom event properties are free-form data that you supplied when tracking. The CLI prints them verbatim. If they contain personal data, that is personal data in your database — see the privacy page.

sessions

The session log, newest first.

sumami-client sessions --db ./sumami.duckdb 3f2a... --limit 3

timeseries

Page views over time, hourly or daily depending on the window.

sumami-client timeseries --db ./sumami.duckdb 3f2a... --from 30d
DATE          VIEWS
2026-01-01      412
2026-01-02      388
2026-01-03      501

export

Export the data of one website as JSON or CSV.

sumami-client export --db ./sumami.duckdb 3f2a... pages --format csv > traffic.csv
sumami-client export --db ./sumami.duckdb 3f2a... summary --format json > traffic.json

The report comes after the website id and names what to export: summary, pages, referrers, browsers, events, sessions or timeseries. The format is json (the default) or csv.

Write the output to a file rather than to the terminal when you are exporting a large window; the table format is for reading, the export format is for feeding into something else.

prune

Enforce the retention window: delete sessions and events older than the configured number of days. 0 days means keep everything, so nothing is deleted. 

# local file — opened read-write for this command only
sumami-client prune --db /var/lib/sumami/sumami.duckdb 3f2a...

# through a running server — goes through the authenticated API
sumami-client prune --url http://127.0.0.1:3999 --username admin --password '...' 3f2a...

Prune the server's own copy through the API while the service is running — never point the CLI at a database file the server currently has open.

erase

Delete a website and all of its data. This is the "right to be forgotten" button: erase removes the website, its sessions and its events. 

sumami-client erase --db /var/lib/sumami/sumami.duckdb 3f2a...

It asks for confirmation unless --yes is given. In HTTP mode it calls DELETE /api/websites/:id.

JSON output

Every command accepts --json, which is what you want in a script: 

sumami-client pages --db ./sumami.duckdb 3f2a... --json | jq '.[0].url'
[
  { "name": "/posts/hello", "value": 312, "url": "/posts/hello" },
  { "name": "/posts/world", "value": 254, "url": "/posts/world" }
]

Credentials

In HTTP mode, when you give --username and --password, the token is cached in ~/.config/sumami/credentials.json with mode 0600, so later commands can be run without repeating the password. Pass --token to bypass the cache entirely. 

sumami-client summary --url http://127.0.0.1:3999 --username admin --password '...'
sumami-client summary --url http://127.0.0.1:3999          # uses the cached token

The login subcommand does the same thing up front: it checks the credentials against the server and stores them. 

sumami-client login http://127.0.0.1:3999 --username admin
# the password is asked for interactively when --password is omitted
credentials saved to /home/you/.config/sumami/credentials.json
logged in to http://127.0.0.1:3999

Safety rules

  • The CLI opens a local database read-only, except for prune and erase.
  • It never writes to a database the server currently has open.
  • Destructive operations in HTTP mode go through the authenticated API, so they are subject to the same authorisation as everything else.
  • Output is truncated to --limit rows (default 50) so a stray command cannot flood your terminal. export ignores --limit and writes up to 10000 rows.

Examples

Yesterday's top pages

sumami-client pages --db ./sumami.duckdb 3f2a... --from yesterday --to today

A weekly report as CSV

sumami-client export --db ./sumami.duckdb 3f2a... pages --format csv --from 30d > last-30-days.csv

Counting unique visitors per day

sumami-client timeseries --db ./sumami.duckdb 3f2a... --from 7d --json | jq 'map(.value)'

Auditing a running server

sumami-client websites --url http://127.0.0.1:3999 --username admin --password '...'
sumami-client summary --url http://127.0.0.1:3999 --username admin --password '...' --from 30d
